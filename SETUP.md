# BetterInternet Final 1.1 preview — browser deployment

## Update the same final-preview deployment
1. Export your current schools as JSON backups first. Keep Draft 3 intact. Reuse the existing Firebase project and the same Vercel hostname to preserve browser storage and cloud account IDs.
2. In Vercel, open the BetterInternet final-preview project → Settings → Environment Variables. Add `FIREBASE_WEB_CONFIG` for Production (and Preview only if needed). Value: the Firebase web app configuration as strict JSON, not JavaScript. Use double quotes on keys and values. Example (replace placeholders yourself):

```json
{"apiKey":"YOUR_WEB_API_KEY","authDomain":"YOUR_AUTH_DOMAIN","projectId":"YOUR_PROJECT_ID","storageBucket":"YOUR_STORAGE_BUCKET","messagingSenderId":"YOUR_SENDER_ID","appId":"YOUR_APP_ID"}
```

Never paste a service account, OAuth client secret or private key. This value is emitted into the deployed browser JavaScript by design; Vercel prevents committing it to GitHub, not viewing it on the site. Keep Firebase client API restrictions appropriate to the services in use. See https://firebase.google.com/docs/projects/api-keys. If GitHub flagged the previous key, verify the exact type and restrictions before resolving the alert; old commits remain. Revoke/rotate genuine private or unsafe credentials and update any deployments using them.
3. In the existing dedicated Firebase project, Firestore Database → Rules, publish the new `firestore.rules` from this package. The new deletion guard prevents school writes during account deletion. Do not overwrite unrelated apps' rules. The project must already have Google and Email/Password auth enabled and the correct Vercel hostname in Authentication → Settings → Authorized domains.
4. On the `final-preview` GitHub branch, upload/replace all nine root website/build files: `index.html`, `accounts.js`, `cloud-sdk.js`, `studio11.js`, `auth-action.html`, `firebase-config.js` (leave this placeholder untouched), `favicon.svg`, `build.mjs`, `vercel.json`. Do not upload `dist/` or your actual config. No CLI needed. Upload README and SETUP optionally. The included Vercel config runs `node build.mjs` and serves `dist`. If Vercel has manual overrides, set Framework Other, build command `node build.mjs`, output directory `dist`. Redeploy after env changes. Without the variable the app intentionally works in guest mode only.
5. After confirming the new deployment loads, Firebase → Authentication → Templates → Email address verification → Custom action URL: `https://YOUR-ACTUAL-VERCEL-HOST/auth-action.html`. This page also handles password reset and email recovery actions; test with fictional accounts. Leave the default if your console won't accept it. The app supplies a return URL to `/studio?verified=1` even with the default email handler. Set sender/public-facing project name to BetterInternet where editable; Firebase controls the email body. Never share an email action link or code.

## Verify with fictional data
- Sign in. Confirm account name/email prefix and cloud status are visible. A preexisting local school is not automatically uploaded: click Save to cloud. New signed-in schools and duplicates auto-save (notice in account UI). Wait for Saved to cloud. Open incognito and sign in with the same account. Verify the last available cloud school restores; local-only schools/images remain on the original device.
- Edit the same school in two browsers and confirm conflicting revisions don't silently overwrite. Verify a second account cannot list, read or write the first account's schools, using the Rules Playground/emulator or an authorized test client. Verify unverified accounts cannot read/write. Sign out. Local caches are scoped but not encrypted, not an access-control boundary on a shared machine. Export before clearing site data.
- On a disposable verified account only, test account deletion. It reauthenticates, creates a write-blocking marker, deletes school documents then deletes the login. Not atomic; a partial failure requires retry, some school data may already be deleted. A minimal UID deletion marker remains in Firestore to prevent stale writes; it has no school content. Browser copies on other devices are not remotely erased. Verify deletion in the Firebase console.
- Try six layouts, renaming, duplication, copy/move floors, tracing a PNG/JPG locally, and saving/sharing a fictional proposal. Report email opens your email app; print to PDF and manually attach if desired. No direct email sending or live sharing with other users in this version.
- Do not use real campus data until live authentication and rules are verified and organizational permission is confirmed. App Check is not enabled; configure it before a wider rollout.

## Scope
Final 1.1 improves editor interactions and account workflow while retaining the Draft 3.7 engineering engine. Floor images are local-only; PDF import requires converting a page to an image outside the app. This is a preview, not a complete release. Advanced recommendation logic, full editor redesign, live collaboration, live Firebase security validation and Safari testing remain outstanding. School data is limited to 800,000 UTF-8 bytes per cloud document; saved proposals are capped at five per school.
